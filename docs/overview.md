# r1metal documents

The index of the docs and the source tree. What r1metal is, and how to build and flash a device, back it up and put Rabbit's firmware back, is in [r1metal](../README.md).

Every page follows two rules:
- It states what is true now, in the present tense; git holds the history.
- Each fact lives on one page; other pages link to it.

## Source tree

Each crate is split by concern, one module per concern, named for it; a file that grows to hold two is split. A `pub` module's `//!` line names its concern. Paths are relative to the crate's directory under `crates/`.

## Conventions of the source

- `rustfmt.toml` sets 120-column lines; `cargo fmt --all` is the only formatter.
- Names, comments and tests follow [Architecture](architecture.md#names-comments-and-tests).
- A value the code decides by is a named constant, and comes from a measurement, a standard, the kernel, Rabbit's driver, or the owner's choice.
- Text has no em dash, no en dash and no hyphen standing for one: a comma, a colon, parentheses or two sentences instead; a range is written `X to Y`.
- A change states its facts where they live, in the same commit: the page that holds each fact, the module's `//!`, and every comment it makes untrue.
- A commit message is one imperative subject line, with a body only where the why is not plain; it tells no history, and like everything in the repository it names no person, computer or path on one.
- A change to the interface follows the [Style guide](app/style-guide.md), and the shot renders are its check.
- Code follows [Architecture](architecture.md): the rules every change follows, one home for each concept, and the shape of the code.
- The gates are listed in [r1metal](../README.md#develop).
